# Arcane Archivist Living Spec - 0.9

## Goals

- Prepare the game for release by hardening performance, accessibility, save integrity, and device support.
- Eliminate major content and systems risk while preserving the exact intended `1.0` feature scope.
- Make sure the game behaves predictably on desktop, mobile, and web targets.

## Player Experience

- The player can pick up the game on multiple devices and continue the same save without confusion.
- The interface remains readable and operable under different screen sizes and input methods.
- The game should feel finished in structure even if some polish work remains for `1.0`.

## Systems

- Platform readiness:
  - Test and tune performance for desktop, mobile, and web.
  - Confirm asset budgets, memory usage, and load times stay within target envelopes.
  - Target envelope: 60 fps on desktop, 30 fps on mobile and web, with scene transitions under 5 seconds on a warm load.
- Accessibility:
  - Add text scaling, colorblind-safe presentation options, and readable contrast modes.
  - Ensure all important information is available without relying on color alone.
- Input abstraction:
  - Finalize unified input actions for keyboard, mouse, controller, and touch.
  - Verify all screens are navigable without precision-only interactions.
- Save and recovery:
  - Harden save versioning and failure recovery.
  - Ensure interrupted sessions recover cleanly across platforms.
  - Autosave on safe transitions and on application pause or backgrounding.
- Production hardening:
  - Add crash-resistant edge case handling for invalid content, missing assets, and unsupported device states.
  - Finalize telemetry or diagnostic logging if used by the project.

## UX/Input

- Mobile layouts must adapt without hiding critical controls.
- Controller focus and touch hit areas must be tested on every major screen.
- Long tooltips and dense panels must have alternate presentation for small screens.
- Post-run and failure summaries must remain readable at compact sizes.

## Content Scope

- No major new gameplay systems.
- No major new content families beyond small polish-only additions.
- Any additions should support quality, not broaden scope.

## Technical Notes

- Run target-device verification against each major screen and traversal flow.
- Validate that the save system tolerates interrupted writes and migration between versions.
- Remove or isolate any prototype-only code paths that could destabilize release builds.
- Keep a release checklist for platform certification-like readiness, even if formal certification is not required.
- Web support is treated as modern desktop browser support; unsupported browsers are excluded from the release envelope.

## Acceptance Criteria

- The game is playable on desktop, mobile, and web target profiles.
- Keyboard, mouse, controller, and touch input all support the full release flow.
- Save/load and resume work reliably across supported platforms.
- Accessibility options are present and affect real gameplay and UI readability.
- No critical crash, corruption, or blocked-progress issue remains in the intended release flow.
- The target device matrix is explicitly documented and verified before release.
