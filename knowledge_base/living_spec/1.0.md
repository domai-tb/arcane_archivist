# Arcane Archivist Living Spec - 1.0

## Goals

- Deliver the full planned feature set of Arcane Archivist as a complete cozy academic fantasy game.
- Support desktop, mobile, and web play with controller, mouse, and touch input.
- Include all major systems described by the design doc except modding and other user-extensible plugin systems, which remain post-`1.0`.
- Ship only when the release criteria can be verified on the supported target matrix.

## Player Experience

- The player manages a living arcane library above a shifting dungeon.
- Sessions move fluidly between patron requests, archive planning, dungeon dives, relic curation, research, defense events, and progression choices.
- The game should feel cohesive, readable, and complete across the full arc from first request to late-game build specialization.

## Systems

- Library management:
  - Persistent hub layout with rooms, stacks, research facilities, workshops, archive wings, and pressure-sensitive stations.
  - Adjacency bonuses and room placement synergies are fully supported.
- Procedural dives:
  - Top-down roguelike dungeon generation with multiple biome or theme variants, secret spaces, elite encounters, and reward routing.
  - Insight cards drive actions, spells, and utility choices during dives.
- Cards and relics:
  - Full insight card pool, card synergies, relic sets, tome combinations, tag interactions, and reward generation rules.
  - Cards and relics interact cleanly with the shared modifier pipeline.
- Progression:
  - Essence, wing upgrades, faction reputation, curse or modifier selection, archive records, and unlock paths are all live.
  - Difficulty modifiers and reward tradeoffs are a stable part of the game.
- Narrative:
  - The overarching story about the library and the labyrinth is complete.
  - Patron factions, repeat visitors, and story beats unlock through play and choices.
- Base defense:
  - Hostile attack events can threaten the library while the player continues to manage other systems.
  - The player can switch between direct control and assigning tasks or automated responses.
- Save and continuity:
  - Run state, persistent library state, progression, narrative unlocks, and accessibility settings all save correctly.

## UX/Input

- Full controller, mouse, keyboard, and touch support for navigation, selection, card play, placement, and confirmation flows.
- Responsive layouts for desktop, mobile, and web breakpoints.
- Clear hub/dive mode indicators, tutorial help, and context-sensitive tooltips.
- Accessibility options are discoverable from the first release build and can be changed in-session where sensible.

## Content Scope

- Full release content across all major systems:
  - Enough requests, tomes, relics, cards, rooms, enemies, and story beats to support replayable long-term play.
  - Distinct library wings, patron factions, and difficulty modifiers with meaningful variety.
  - A complete card and relic catalogue that supports the intended build archetypes.

## Technical Notes

- Godot scenes and data resources remain the implementation foundation for all systems.
- External content files should continue to define cards, relics, requests, room templates, and modifiers.
- The save format must be versioned and migration-ready.
- Performance and memory budgets must be valid on the weakest supported target, not only desktop.
- Modding and plugin APIs are intentionally excluded from the `1.0` release boundary, though the data model should remain clean enough to support them later.
- `1.0` is a release gate, not a broadening milestone: unresolved core-system bugs or unsupported target failures block ship.

## Acceptance Criteria

- A player can start, progress through, and finish a full campaign flow without missing core systems.
- Desktop, mobile, and web builds all provide the intended gameplay.
- Controller, mouse, and touch input can complete the full release loop.
- All core gameplay pillars from the design doc are represented and connected.
- The game feels feature-complete, polished, and internally consistent.
- Supported target builds pass a documented smoke-test matrix covering launch, save/load, run completion, and UI navigation.
