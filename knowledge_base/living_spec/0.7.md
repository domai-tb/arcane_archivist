# Arcane Archivist Living Spec - 0.7

## Goals

- Bring the game to content-complete core loops: library, dives, cards, relics, requests, progression, and pressure events all exist together.
- Fill out enough content that the player can complete a full session arc without seeing placeholder-only systems.
- Keep the game in single-player scope and avoid post-launch ambitions such as co-op or public modding.

## Player Experience

- The player can spend a full play session rotating between request selection, archive planning, dungeon dives, and pressure recovery.
- There is enough content density that repeated dives feel distinct because requests, rooms, relics, and card choices vary.
- The library feels like a real evolving workplace with named patrons, visible wings, and strategic upgrades.

## Systems

- Request chains:
  - Add short multi-step request chains that span multiple dives.
  - Each chain ends in a stronger reward than one-off requests.
  - Each chain must have at least one success state, one partial-progress state, and one fail-or-expire state.
- More dungeon structure:
  - Introduce distinct biome or theme variants for dungeon floors.
  - Each variant has its own enemy sets, hazards, and reward rooms.
  - Every new theme must alter at least two of enemy pool, hazard set, route pressure, or reward structure.
- Expanded pressure and defense:
  - Archive pressure events now include a fuller set of disruptions.
  - Defense encounters can threaten a station, shelf, or visitor area.
- Advanced archive planning:
  - Library wing choices, relic placement, and station placement all matter at once.
  - The player can respec some placement choices at a modest cost.
- Card economy:
  - Card rewards and deck refinement are broad enough to support several archetypes.
  - Temporary run-only card effects can appear from special rooms or patron help.

## UX/Input

- Add a clearer library overview screen that summarizes requests, wings, pressure, and active bonuses.
- Make dungeon theme selection readable before the dive begins.
- Show chain progress and next-step requirements in a compact request tracker.
- Expose defense threats with clear warnings and costed response options.

## Content Scope

- 16-20 patron request templates.
- 3 or more dungeon theme variants.
- 24-30 total insight cards.
- 12-16 catalogable relics.
- 8-10 archive bonuses or set effects.
- 4-5 pressure disruption types.
- 2-3 small defense encounter variants.

## Technical Notes

- Standardize all content on stable IDs and tags before the content count expands further.
- Ensure request chains can survive save/load and partial completion.
- Add migration support for previous save versions now that multiple progression layers exist.
- Keep theme-specific content reusable through tags rather than hardwired branching logic.
- 0.7 is the last milestone that should add breadth without a separate design review.

## Acceptance Criteria

- The player can complete a multi-step request chain.
- At least three dungeon theme variants are clearly different in play.
- Archive pressure can threaten more than one type of library asset.
- The player can replan the library around existing placements without starting over.
- Repeated playthroughs reveal meaningful build variety rather than only stat inflation.
- A single run can exercise requests, archive planning, dungeon themes, and pressure response without requiring a debug path.
