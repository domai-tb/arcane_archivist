# Arcane Archivist Living Spec - 0.4

## Goals

- Add the second major loop: patron service and research between dungeon dives.
- Make dungeon rewards matter outside the run through tome recovery, relic deposits, and essence.
- Establish the first clear rhythm: accept requests, dive for knowledge, process findings, improve the library, repeat.
- Keep scope narrow enough that the loop can be tuned before adding heavier progression.

## Player Experience

- The player feels like a magical librarian, not only an adventurer.
- Visitors arrive with readable needs, deadlines, and rewards.
- The library becomes a calm planning space where recovered materials are sorted into useful outcomes.
- Dives gain purpose because rooms, enemies, and treasure are tied to active requests.
- Finishing a request should feel like closing a small story: a patron gets an answer, the archive grows, and the next opportunity appears.

## Systems

- Patron service board:
  - Generates a small queue of patron requests instead of only one active objective.
  - Each request asks for one or more knowledge tags, tome fragments, relic samples, or essence quantities.
  - Requests have a simple state machine: queued, active, in progress, completed, expired.
  - Deadlines are measured in completed dives or library turns, not real time.
  - Expired requests leave the queue and can be replaced by a new request; they do not block the save.
  - Requests offer rewards such as essence, card unlocks, room blueprints, visitor reputation, or story hints.
- Research desk:
  - Converts recovered tomes and relic samples into completed request progress.
  - Uses short timed jobs measured in library turns, not real time.
  - Allows one active research job at a time in this version.
  - If a request is tied to research, partial progress is saved and shown in the UI.
- Library layout foundation:
  - Adds placeable functional stations: request board, research desk, archive shelf, and essence lamp.
  - Uses a simple grid or snap-point layout.
  - Adjacency bonuses are limited to one rule: archive shelves next to the research desk reduce research time.
  - Essence is the basic library-side spend currency for rerolls, short research acceleration, or a single respec action.
- Dungeon objective tagging:
  - Dives display active request targets before descent.
  - Dungeon rooms can contain tagged rewards that satisfy request needs.
  - Extraction returns tagged materials to the library inventory.
- Card and relic continuity:
  - Dives continue to use the existing card-driven action loop.
  - Recovered relics are library resources first, not permanent build-defining items yet.
  - A small reward pool unlocks new insight cards through request completion.

## UX/Input

- Add a library mode UI with three primary actions: inspect requests, start research, arrange stations.
- Add a pre-dive panel showing active request targets and likely dungeon reward tags.
- Add a post-dive summary grouped by request relevance: useful finds, surplus finds, essence gained.
- Input should stay consistent between modes: move, inspect, confirm, cancel, and open card or relic details.
- Tooltips must explain request tags, research time, deadline remaining, and adjacency effects.

## Content Scope

- 6-8 patron request templates.
- 4 knowledge tags: forbidden history, beast lore, astral theory, wardcraft.
- 4 placeable library stations.
- 7-9 tome fragment types or tagged pickups.
- 10-12 relics total, including at least 4 relic sample types usable for research.
- 12-16 insight cards total, including at least 2 unlocked through requests.
- 2 dungeon reward room templates intentionally serving active requests.

## Technical Notes

- Store requests, knowledge tags, card rewards, station definitions, and request state as data resources.
- Keep request generation deterministic from the current save seed where practical.
- Separate library inventory from run inventory.
- Persist library layout, active requests, completed requests, research jobs, unlock flags, and request queue order.
- Avoid hard-coding patron text into systems; content should be replaceable for future modding.
- The queue should be recomputed from stored request data after load instead of serialized as an opaque blob.

## Acceptance Criteria

- The player can accept at least one patron request, enter a dive, recover a relevant tagged item, extract, research it, and complete the request.
- Completing a request grants a visible reward and can unlock at least one new card.
- Library station placement persists after saving and loading.
- The research desk adjacency bonus works and is explained in UI.
- A post-dive summary clearly shows which recovered items advanced active requests.
- The game remains playable if the player ignores requests and simply dives, but progress is slower.
- An expired request is removed cleanly and replaced without corrupting the queue or save.
