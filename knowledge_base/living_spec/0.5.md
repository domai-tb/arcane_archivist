# Arcane Archivist Living Spec - 0.5

## Goals

- Integrate library management, dungeon dives, cards, relics, and requests into one coherent Arcane Archivist identity.
- Make choices in the library meaningfully alter dive strategy.
- Make dive outcomes alter library planning beyond simple resource turn-in.
- Introduce the first version of archive pressure so the library can be threatened without full base defense complexity.

## Player Experience

- The player plans like a librarian and improvises like a roguelike explorer.
- A typical session has satisfying decisions before, during, and after each dive.
- Library layout begins to express build identity through adjacency and station choices.
- Visitors, research, and relic handling make the hub feel alive.
- The player starts recognizing synergies: a room layout supports a research style, which unlocks cards, which changes the next dive.

## Systems

- Integrated preparation:
  - Before a dive, the player chooses one active request as the primary expedition focus.
  - The primary focus biases dungeon rewards and room events toward matching knowledge tags.
  - The player equips a small loadout of insight cards unlocked by prior research.
- Relic cataloging:
  - Recovered relics can be cataloged into the archive for persistent passive library effects.
  - Each cataloged relic has a tag and a placement affinity.
  - Relics placed near compatible stations improve request rewards, research speed, or pre-dive scouting.
- Expanded library adjacency:
  - Stations and cataloged relics use simple orthogonal adjacency rules.
  - Bonuses should be legible and low-stack to avoid unreadable optimization.
  - Example effects: faster astral research, extra essence from beast lore requests, or one additional pre-dive room preview.
- Archive pressure events:
  - Completing research and cataloging unstable relics increases an archive pressure meter.
  - At thresholds, a short disruption occurs in the library: cursed shelves, visitor panic, damaged station, or corrupted request.
  - Corrupted requests pause the affected request until repaired or replaced.
  - Damaged stations are disabled until repaired with a short action or essence cost.
  - Pressure decays by one step after a successful disruption resolution or after a completed request.
- Card and relic interactions:
  - At least some insight cards gain additional effects when the player has cataloged matching relic tags.
  - Relic effects are intentionally modest but noticeable, supporting experimentation without breaking dives.
- Visitor reputation:
  - Request completion builds reputation with visitor archetypes.
  - Reputation affects request quality and occasional narrative dialogue.

## UX/Input

- Add a pre-dive planning screen with primary request, equipped cards, relevant relic bonuses, and risk level.
- Add a library overlay that visualizes adjacency bonuses and pressure sources.
- Add concise event prompts for archive pressure disruptions with clear costs and outcomes.
- Add card detail panels that show active relic-linked modifiers.
- Add visitor reputation display without making it a dominant management screen.

## Content Scope

- 10-14 patron request templates across at least 3 visitor archetypes.
- 6-8 catalogable relics with placement affinities.
- 6 placeable or functional library objects, including at least 2 that interact with relic placement.
- 14-18 insight cards total.
- 3 archive pressure disruption types.
- 3 defensive or hazard micro-encounters reused from dungeon mechanics.
- 4-6 short visitor dialogue beats tied to reputation or completed requests.

## Technical Notes

- Build a shared tag system used by requests, tomes, relics, cards, stations, and dungeon rewards.
- Keep pressure events data-driven so new disruptions can be added without changing core flow.
- Implement library bonuses as composable modifiers, not bespoke station scripts.
- Ensure dive generation can accept a primary request bias while preserving procedural variety.
- Save cataloged relic placements, reputation, pressure state, equipped cards, and active modifiers.
- The pressure state should be fully derivable from explicit counts and flags so save/load cannot drift.

## Acceptance Criteria

- Choosing a primary request before a dive visibly affects dungeon rewards or room events.
- At least one cataloged relic modifies a library process and at least one modifies a card effect.
- Archive pressure can rise, trigger a disruption, and be resolved through a clear player choice or encounter.
- Library adjacency bonuses can be inspected before committing to placement.
- A player can describe a basic build path, such as fast research, essence gain, safer scouting, or card synergy.
- The combined loop feels continuous: request choice affects dive, dive rewards affect library, library state affects the next dive.
- Pressure decay or recovery is visible in UI and does not require hidden knowledge.
