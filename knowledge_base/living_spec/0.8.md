# Arcane Archivist Living Spec - 0.8

## Goals

- Polish the core game into a balanced, readable, and rewarding experience.
- Tune difficulty curves, reward cadence, and system interactions so the full loop is satisfying rather than merely present.
- Improve presentation quality, onboarding clarity, and moment-to-moment legibility.

## Player Experience

- The player should understand why a build works and where its weak points are.
- Each run should present a fair sequence of tradeoffs: request pressure, dungeon risk, archive upkeep, and reward selection.
- The library and dungeon should feel like one coherent fantasy system, not separate minigames.

## Systems

- Balance pass:
  - Rework card values, relic effects, request rewards, and pressure thresholds.
  - Reduce dominant strategies and support multiple viable archetypes.
  - At least three build archetypes should be testable with clear strengths and weaknesses.
- Onboarding:
  - Add clearer tutorial prompts and optional guidance overlays.
  - Teach card tags, request tags, archive bonuses, and pressure states gradually.
  - Tutorial content must be skippable and should not reappear after the player opts out.
- Content depth:
  - Expand enemy families, room hazards, and patron request variety where gaps remain.
  - Add a few high-end rewards that are exciting without being mandatory.
- Quality-of-life systems:
  - Add deck sorting, archive filtering, and request tracking shortcuts.
  - Improve save-slot clarity and in-session state recovery.
- Audio/visual polish:
  - Better feedback for card usage, request completion, archive pressure, and reward reveals.

## UX/Input

- Ensure tooltips are consistent, concise, and context aware.
- Add better controller navigation hints and focus states.
- Provide readable state banners for hub, dive, research, and pressure situations.
- Ensure all reward and failure states have clear post-action summaries.

## Content Scope

- 30-36 total insight cards.
- 18-24 catalogable relics.
- 20-24 request templates across all active chains.
- 4-5 dungeon theme variants.
- 8-10 pressure or defense event variants.
- 6-8 archive set or wing specialization paths.

## Technical Notes

- Refactor any brittle card or relic logic into shared effect pipelines if still needed.
- Harden validation for content authoring so balance changes do not silently break saves or reward tables.
- Stabilize performance hotspots in generation, UI refresh, and save serialization.
- Add regression checks for interaction states and reward distribution.
- Balance target should be documented per archetype so tuning can be measured, not guessed.

## Acceptance Criteria

- The player can explain their build using visible game information alone.
- Multiple build archetypes are viable over several full runs.
- Tutorial guidance does not interrupt experienced players unnecessarily.
- Reward pacing and failure recovery feel fair in extended play.
- The game is stable enough that balance iteration is the main remaining work.
- The player can disable all hints and still understand the state of the run from UI alone.
